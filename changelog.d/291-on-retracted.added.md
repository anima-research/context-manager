- `ContextStrategy.onRetracted(rows, ctx, { undone, removed })`: the strategy hears rows as they leave the agent's window (agent-framework #291), with the rows that left, in the order the window held them, every shard of a body, and a context whose view no longer holds them. `retractRows` calls it once per call, after the rows are out and before it returns, with `undone` as given and `removed: false`; a row the store no longer holds, taken out by its id, isn't given, since there is no row to give. Once a host presents rows on a branch, a removal through the manager (`removeMessage`, `removeMessages`) of rows the window held calls it with the rows as they were before they went, `removed: true`. In legacy mode a removal calls nothing: the window is the record, and a strategy that folded the row keeps what it folded, as before. Fire and forget, as `onPresented` (#288): a throw or a rejection is logged as `Strategy onRetracted failed for …`, naming the rows, and the rows stay out. A tombstone write cut short tells the strategy the rows it took out before it. While the strategy initializes, the calls wait and are made in order once it has, before the rows presented meanwhile are heard; a row presented again since is still given, and a row the initialized branch's window holds at the ordinal it left (a branch made before it left), or any row while that branch is in legacy mode, is left out.
  - `AutobiographicalStrategy` (and `KnowledgeStrategy`) let go of what covers a row that left: each L1 with the row among its sources is dropped, with every summary above it, and a summary the drop leaves without its parent renders and merges again; each chunk record holding the row gives it up and is compressed again over the rows it keeps (one left with none is removed). The summaries, chunk records and merge queue are written at once, with one `[autobiographical] … row(s) left the window` warning naming what changed. A compression or merge in flight over the row writes nothing when it lands. So an undone turn's rows no longer render folded after the undo, and a redo, which presents them again at the end of the window, renders each once, raw there until it is folded again, where it rendered twice before (raw, and inside the summary at its old place). The cost is the fold work over those rows: the summaries above them are written again. In legacy mode nothing changes. `PassthroughStrategy` and `WindowedPassthroughStrategy` define no `onRetracted`.
