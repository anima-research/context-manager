- Window reads for a host that presents rows (agent-framework #291).
  - `windowStatusOf(id)` says where a row stands with the manager's window, before the view filter, as the new exported `WindowStatus` type: `'in'` the window, `'out'` of it (stored and not presented, or taken out without `undone`: exactly the rows `getUnpresentedMessages()` lists, so an undone shard is `'out'` while a shard of its body before it is in the window), `'undone'` (an undone turn's row, which that list leaves out until a redo), or `'absent'` (no slot the manager merges holds it). In legacy mode every row the merged slots hold is `'in'`. A row removed through another manager reads `'absent'` while this manager's `ordinalOf` still gives its ordinal, so a host can tell which rows to take out of each other window. It reads no row's content and writes nothing.
  - `branchSequenceOf(messageId)` gives the sequence `branchAt(messageId)` cuts at, without making a branch, for a host that accounts for a cut (the rows a rollback leaves out of the record, and those it keeps there but not in the window). It throws `Message not found` as `branchAt` does.
  - `getUnpresentedMessages({ afterSequence })` lists only the rows stored after the sequence, the same rows the whole listing gives with a greater sequence, found by a binary search over the record, so a call walks only the rows stored since. It throws a `TypeError` for an `afterSequence` that isn't a number.
  - `resetHeadWindow(text, { metadata })` stores the `[Topic Transition]` message with the metadata given. Once a host presents rows on the branch, the transition is presented before the head window is reset to start at it, so the head window starts at a row the window holds and the strategy hears it at its presentation; before, it was stored and not presented. A presentation that fails rejects naming the stored message, without resetting the head window. In legacy mode nothing more is written.
