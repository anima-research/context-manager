- `switchBranch()` and `fork()` no longer leave the manager initialized for the branch that the store left when the store selects the branch and then fails to save the selection. Chronicle 0.6 and 0.7 keep such a selection in effect. Chronicle 0.8 undoes it, so there the switch is a refusal, as before. The call now rejects, saying that the switch took effect and that `getStore().sync()` saves it, and the manager refuses work until `setStrategy(getStrategy())` initializes it on the branch.
