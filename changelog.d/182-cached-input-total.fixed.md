- A compression attempt's provider input count adds cache writes and cache reads to `inputTokens` for every provider, not only for Anthropic and Bedrock (#182). membrane 0.5.81 and later state those three counts as disjoint for every adapter whose convention they know, so on the other providers that report cache reads, OpenAI's adapters and OpenRouter, the count left out the cached span. A refused or incomplete compression's fallback plan then took a baseline too small, and could send an expanded fallback that doesn't fit the compression budget instead of recording it as `admission_rejected`. A successful attempt's `renderedTokens` under-reported its prompt by the same span.
  - **Host operators:** on those providers, a fallback that doesn't fit is now `admission_rejected` and not sent, as on Anthropic and Bedrock, and `renderedTokens` includes the cached span. A full cache hit, no fresh input beside a positive cache read, now counts as the provider's count of the prompt there too, where before the complete request bound stood in for it.
  - **Gemini:** membrane marks Gemini's cache convention unknown until antra-tess/membrane#109, and passes its counts through with the cached span inside `inputTokens`. Until a membrane with that change is installed, this counts a cached Gemini prompt's cached span twice: a fallback that fits can be `admission_rejected`, and its chunk can go to quarantine. Install this together with the membrane release that carries that change.
  - The compression budget's accounting version is 3. A chunk quarantined under version 2 may have had its fallback attempts used up by expansions that didn't fit, before one that does, so its version-2 records no longer count toward the per-chunk shape cap. After upgrading it gets a fresh cap of three shapes: one attempt at its current shape, and more only if its shape changes. A re-quarantine raises a fresh `compression:quarantine-alert`, since the alert is keyed by the record. On Anthropic and Bedrock, whose count was already right, the retry usually ends as before, at the cost of its canonical call and any fallbacks that fit; a record names no provider, so the bump can't spare them. Version-2 records stay until the chunk compresses, the paid-off sweep or an operator's clear removes them, or the ledger's checkpoint keeps only its newest 1,024.
  - The `@animalabs/membrane` range is `^0.5.81`, the first release that states cached input apart from fresh input.
