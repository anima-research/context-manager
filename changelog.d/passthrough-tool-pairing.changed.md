- `PassthroughStrategy` and `WindowedPassthroughStrategy` send no tool result without the tool call it answers (#370). A window starts only where every tool result it holds has its call in it: the windowed strategy starts back at that call, or earlier where pairs overlap, where the anchor is on a result, a re-anchor doesn't cut between a call and its result, and passthrough's cut leaves such a pair out whole. A tool result that answers no call in the view is left out before the window is priced, and a message that held nothing else sends `[tool call omitted]`. Where the newest message, back to the latest start that keeps every tool result with its call, doesn't fit the budget, the windowed strategy refuses with `OverBudgetError`, as for a newest message that doesn't fit, and passthrough sends nothing, or refuses beside system changes. A store whose window an earlier release started at a result, or whose view holds a result whose call it doesn't, sends a different request once, at its first compile after the upgrade, so it misses the provider's cache that once, and on a model that binds thinking to the request that minted it, the replies after that point go without their thinking.
