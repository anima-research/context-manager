- `ContextManager.noteThinkingDropped(messageIds, compileId)` (new): a host calls it with the stored replies whose thinking the provider set aside under the drop control (`ThinkingBinding.dropBlock`), in a request of a stream built from the branch's last committing compile with `binds`, naming that compile's `provenance.compileId`. Each id is a body's head as the compile's provenance names it (`RawBodySource.messageId`), the id `addMessage` returned. The record then holds them as set aside, so from the next compile on each goes without it, and the replies after it keep theirs. A noted reply isn't reported in a later `thinkingStrip`. A repeated note writes nothing. It returns false, writing nothing, when `compileId` isn't the compile that wrote the branch's record, and on a branch with no record or one it can't read, or when the store can't write it, as `noteRequestSent` does.
