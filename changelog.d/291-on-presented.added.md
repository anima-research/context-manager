- `ContextStrategy.onPresented(rows, ctx)`: the strategy hears rows as they enter the agent's window (agent-framework #291), with the rows that entered, in window order, every shard of a body, and a context whose view holds them. In legacy mode the window is the record, so the manager calls it from inside each add, as it called onNewMessage: after a holdCompression hold is placed and before `addMessage` returns. Once a host presents rows on a branch, a stored row isn't heard at its add; `presentRows` calls the hook once per call, after the rows are in the window and before it returns. Fire and forget as before (#288): a throw or a rejection is logged, naming the rows, and the rows stay presented. A `presentRows` cut short by a failed write calls the hook with the rows it got in before it throws, and one that completes a body partly in the window calls it with only the shards that entered then. The first `presentRows`, which writes the legacy window down, enters no new row and calls nothing; a row presented again after `retractRows` is heard again; an auxiliary slot's row is heard when a host presents it. Rows presented while the strategy is initializing are heard once it has initialized, those still in the window.
  - A strategy without `onPresented` hears each row through `onNewMessage` at the same points: at its add in legacy mode, and once per presented row, in window order, from `presentRows` once a host presents. A strategy with `onPresented` isn't called through `onNewMessage`. `PassthroughStrategy` and `WindowedPassthroughStrategy` do nothing in either hook and define no `onPresented`, so a subclass that overrides their `onNewMessage` still hears every row.
  - `AutobiographicalStrategy` rebuilds its chunks and starts background compression (`autoTickOnNewMessage`, which keeps its name) from `onPresented`. In legacy mode that is the same work at the same point as before. Once a host presents rows, a row stored and not presented is never chunked or folded, and presenting rows starts the drain. Its `onNewMessage` stays, for a caller that drives the strategy directly, and does the same work.
