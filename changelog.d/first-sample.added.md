- `AutobiographicalStrategy.reportRefusedAsTooLong(stated, overhead)`: tell the store that the provider refused the request its last compile built as too long, with the input count the refusal stated, or `undefined` where it stated none, and the request's overhead, as `reportRealInputTokens` takes it. It returns `{ changed, why }`: `changed` says a retry can now come out different: the store runs a select dry with the refused compile's store, budget and options, and compares the request it returns with the refused one. A message stored since the compile makes them differ too, since a retry would carry it. Where that select refuses, `changed` is false. `why` says in one sentence what the store made of the refusal, followed by that select's refusal where there is one, and the store also logs it. A stated count is the compile's calibration sample, so the method learns only from a compile that armed one, as an adaptive select (`adaptiveResolution`) does. Under `requestLimitTokens`, where the count is more than the store priced the request at, the store also keeps the rate the count implies while that is above its multiplier, and a refusal with no count keeps the calibration's ceiling the same way where the store priced below it. Neither keeps a rate at which what the request sends beside the context leaves it no room under the limit. That rate prices the limit's allowance until a usage sample that declares its overhead replaces it, or one that the calibration's band doesn't reject shows a rate no higher than the multiplier. It's kept in memory. The multiplier itself still moves only by its sampling rules and stays within its clamp.
- `OverBudgetDiagnostics.requestLimitBound`: `true` on a refusal under `requestLimitTokens`, from the autobiographical strategy or a passthrough one, where the limit, not the budget, is the bound it measured against, so a caller can tell a request too big for the limit from one too big for the budget without comparing numbers. It's absent on a budget's refusal. A preview that doesn't fit carries it the same way, as `PreviewResult.requestLimitBound`.
