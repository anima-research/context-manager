- `AutobiographicalStrategy.reportRefusedAsTooLong(stated?, overhead?)`: tell the store that the provider refused the request its last compile built as too long, with the input count the refusal stated, where it stated one, and the request's overhead, as `reportRealInputTokens` takes it. It returns `{ changed, why }`: `changed` says a retry can now fit where the refused request didn't, and `why` says in one sentence what the store made of the refusal, which it also logs. A stated count is the compile's calibration sample. Under `requestLimitTokens`, where the count is more than the store priced the request at, the store also keeps the rate the count implies while that is above its multiplier, and a refusal with no count keeps the calibration's ceiling the same way where the store priced below it. That rate prices the limit's allowance until a usage sample replaces it or shows a rate no higher than the multiplier. It's kept in memory. The multiplier itself still moves only by its sampling rules and stays within its clamp.
