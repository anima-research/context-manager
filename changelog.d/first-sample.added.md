- `AutobiographicalStrategy.reportRefusedAsTooLong(stated, overhead)`: tell the store that the provider refused the request its last compile built as too long, with the input count the refusal stated, or `undefined` where it stated none, and the request's overhead, as `reportRealInputTokens` takes it. It returns `{ changed, why }`: `changed` says a retry can now come out different. It's false where a retry would be the same request: the refused request, at what the store now prices it at, would still fit the request limit, if there is one, and the refusal didn't raise the multiplier or the window still fits the budget at the raised one. `why` says in one sentence what the store made of the refusal, which it also logs. A stated count is the compile's calibration sample, so the method learns only from a compile that armed one, as an adaptive select (`adaptiveResolution`) does. Under `requestLimitTokens`, where the count is more than the store priced the request at, the store also keeps the rate the count implies while that is above its multiplier, and a refusal with no count keeps the calibration's ceiling the same way where the store priced below it. That rate prices the limit's allowance until a usage sample that declares its overhead replaces it or shows a rate no higher than the multiplier. It's kept in memory. The multiplier itself still moves only by its sampling rules and stays within its clamp.
- `OverBudgetDiagnostics.requestLimitBound`: `true` on a refusal under `requestLimitTokens` where the limit, not the budget, is the bound it measured against, so a caller can tell a request too big for the limit from one too big for the budget without comparing numbers. It's absent on a budget's refusal.
