- A compile sends a signed `thinking` or `redacted_thinking` block only while the prefix it was minted under holds (#155), on a target that binds thinking to its prefix. On an account that enforces thinking binding, a fold, merge, cap, image strip or raw-form release used to change the prefix of every reply after it, so the provider refused each later request with a 400 ("The block is bound to a different conversation"), or dropped the blocks under `drop_block`. Now each reply is stamped with the prefix it was minted under: the accepted compile's chain, extended by what the namespace stored after that compile, as the walk read it. The system prompt and tools are in that chain only when the host passes `SelectOptions.prefixIdentity`. A reply minted under a compile whose acceptance hasn't come in, and which sent something else, waits for that acceptance instead, and is stamped at the next walk after it. A compile strips the thinking whose prefix changed, and the thinking after the first block that changed within its message. Thinking with no stamp doesn't render: a summary's carriers, replies stored before the branch's first accepted round, a reply stored after a sharded body in the same request, and a reply stored on another branch than the one its round was compiled on. The pass covers every strategy, and engages at the namespace's first `acceptRound`; a store whose host never accepts a round renders as before. A compile whose message the strip empties moves that message's cache breakpoint to the message before it, if there is one.
- Stripped thinking is released from the strategy's view on that branch, so budgets and estimates count what is sent. A compile whose prefix identity or system injections differ from those of the branch's last accepted compile (a one-turn system change) strips without releasing what was minted under that compile's, and that thinking comes back when they do. With system injections that change every turn, each reply's thinking is released at the second compile after it. Stamps, releases and each accepted compile's chain are Chronicle typed records (`context-manager/thinking-binding`), one per accepted compile, so a reopened store keeps what its last record held. What the process learned after that record is gone after a reopen: the stamps of replies stored since, the compiles bound since, the host's releases since, and the releases a new branch took from the one it was made from. Those replies are stamped again from the store as it stands, and the host releases again a block the provider refuses again.
