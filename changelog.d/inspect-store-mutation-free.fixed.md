- `scripts/inspect-store` is mutation-free strategy inspection. It used to open a live `AutobiographicalStrategy` under a `ContextManager` with a config that was not the resident's, which registers state for whatever namespace it is given and can chunk the frontier with the wrong window and chunk size. It also always ran a 50K-token sample compile, which is where a household's `OverBudgetError` came from. Now it opens the store with `JsStore.open` (it never creates one), reads the strategy's persisted state as stored, and constructs no strategy or `ContextManager`, so it creates no strategy, chunk or namespace state.
  - `--namespace <ns>` names the strategy namespace (`--ns` still works). A namespace without strategy state is reported, with the namespaces that have it, and nothing is inspected (exit 2).
  - The sample compile runs only with an explicit `--sample-compile <tokens>`. That run is a live, audit-only open, and it registers the namespace's states and may migrate legacy chunk records, so use it on a copy.
  - Chronicle has no read-only open: opening still takes the store's lock and may rewrite its state index, and reading messages re-registers the message slot's history indexes idempotently. Run it on a stopped resident's store or a copy.
