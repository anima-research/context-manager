- Compression prompts replace serialized `data:<mime>;base64,…` URLs of 4096+ base64 characters with a marker naming the media type and size. Imported tool output can carry a whole image as text, which the image-byte cap cannot see and the tokenizer prices as prose, so one image could become hundreds of thousands of tokens. Covers text blocks and tool results in both forms (string and block array), MIME parameters before `;base64`, and JSON-escaped slashes. Only the prompt changes; Chronicle is never mutated.
- Every compression request builder (L1 canonical, L1 source-only, merge, split-stitch) now applies one final projection (`projectCompressionWireMessages`: serialized-media replacement, then the image-byte cap) to the post-split list it actually ships. The split-stitch rung previously applied neither.
