- `reinitializeOnStoreBranch()` initializes a manager's strategy again on the branch its store is on, for a host whose managers share a store (agent-framework #291). Every manager on a store follows its branch, but only the one that moved it, through `switchBranch()` or `fork()`, initializes its strategy again; after a move by `store.switchBranch` or by another manager, `AutobiographicalStrategy` refused every compile ("requires reinitialization for the current branch generation") until a restart, and a `switchBranch()` on each manager in turn left the managers before it stale again, since each switch starts a branch generation of its own. The new call selects no branch and starts no generation: it observes the store's, so every manager on the store can call it after one move, in any order or at once, and all of them end valid. It writes nothing to the record. The window index follows the store's branch on its own, so on a branch made before the manager's write-down `windowMode()` reads `'legacy'` after the call, and `presentRows([])` writes it down. Its recovery contract is `switchBranch()`'s: a superseded call rejects with `InitializationSupersededError` naming the branch it followed, `created` false; a failed one keeps the manager fenced until a later call, `switchBranch()` or `setStrategy()` succeeds; and a store moved again while it initialized rejects it. A manager made by `derive()` is bound to its own branch, so the call initializes its strategy again there.
